# 2.17 - Kontrola Pristupa Funkcionalnostima

## Pregled

Implementacija kontrole pristupa (2.17) u sistemu koristi JWT token-baziranu autentifikaciju i role-based access control (RBAC). Sistem podržava tri uloge:

- **NK (Neautentifikovani korisnik)** - Može se registrovati i prijaviti
- **RK (Redovan korisnik)** - Obična korisnička prava nakon prijave
- **A (Administrator)** - Administratorska prava

## Arhitektura

### 1. JWT Token Management (`internal/security/jwt.go`)

**Komponente:**
- `TokenManager` - Upravlja generisanjem i validacijom JWT tokena
- `Claims` - Sadrži korisničke podatke u tokenu (userID, username, role, email)

**Ključne metode:**
```go
func (tm *TokenManager) GenerateToken(userID, username, email, role string) (string, error)
func (tm *TokenManager) ValidateToken(tokenString string) (*Claims, error)
func (tm *TokenManager) RefreshToken(oldToken string) (string, error)
```

**Token lifetime:** Podrazumevano 24 sata (konfigurabilno preko `JWT_EXPIRY_HOURS`)

### 2. Role-Based Access Control (`internal/security/roles.go`)

**Uloge i njihova hijerarhija:**
```
NK (0) < RK (1) < A (2)
```

**Ključne funkcije:**
```go
func HasPermission(userRole, requiredRole string) bool
func IsAdmin(role string) bool
func IsRegularUser(role string) bool
func IsAuthenticated(role string) bool
```

### 3. Autentifikacijski Middleware (`internal/middleware/auth.go`)

**Middleware-a:**

#### AuthMiddleware
- Obavezna autentifikacija
- Validira JWT token iz `Authorization: Bearer <token>` headera
- Postavlja `user_id`, `user_role`, `user_email`, `username` u context

```go
r.GET("/protected", middleware.AuthMiddleware(tokenManager), handler)
```

#### RequireRole
- Proverava da li korisnik ima potrebne uloge
- Supports multiple roles (OR logika)

```go
r.POST("/admin", 
    middleware.AuthMiddleware(tokenManager), 
    middleware.RequireRole(security.RoleAdmin), 
    handler)
```

#### OptionalAuth
- Opcionalna autentifikacija
- Ako token postoji, validira ga; ako ne, koristi se kao NK korisnik

```go
r.GET("/public", middleware.OptionalAuth(tokenManager), handler)
```

## Tok Autentifikacije

### Registracija
```
POST /register
{
    "username": "korisnik",
    "firstName": "Ime",
    "lastName": "Prezime",
    "email": "korisnik@example.com",
    "password": "Sifra123!",
    "confirmPassword": "Sifra123!"
}

Response:
{
    "message": "registracija kreirana; potvrdi nalog verifikacionim tokenom",
    "verificationToken": "token123",
    "registrationStatus": "pending_confirmation"
}
```

### Potvrda Registracije
```
POST /register/confirm
{
    "token": "token123"
}

Response:
{
    "message": "registracija potvrđena"
}
```

### Prijava - Korak 1 (Lozinka)
```
POST /login
{
    "username": "korisnik",
    "password": "Sifra123!"
}

Response:
{
    "message": "otp generisan (u realnom sistemu šalje se na email)",
    "otp": "123456"
}
```

### Prijava - Korak 2 (OTP → JWT Token)
```
POST /login/verify
{
    "otp": "123456"
}

Response:
{
    "message": "prijava uspešna",
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user_id": "507f1f77bcf86cd799439011",
    "email": "korisnik@example.com",
    "role": "RK",
    "username": "korisnik",
    "expiresAt": 1735732800
}
```

### Magic Link Prijava
```
POST /magic/request
{
    "email": "korisnik@example.com"
}

Response:
{
    "message": "magic link generisan",
    "magicToken": "token456"
}

POST /magic/confirm
{
    "token": "token456"
}

Response:
{
    "message": "magic link potvrđen, prijava uspešna",
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user_id": "507f1f1f77bcf86cd799439011",
    "role": "RK"
}
```

## Korišćenje JWT Tokena

Nakon prijave, klijent koristi token u svim zahtevima:

```bash
curl -H "Authorization: Bearer <token>" http://localhost:8080/api/protected
```

## Admin Akcije (Zahtevaju uloge "A")

### Promena Uloge Korisnika
```
POST /admin/users/{userId}/role
Authorization: Bearer <admin-token>
{
    "role": "A"  // ili "RK"
}

Response:
{
    "message": "uloga korisnika ažurirana",
    "user_id": "507f1f77bcf86cd799439011",
    "role": "A"
}
```

## Konfiguracija

Svi parametri se čitaju iz environment varijabli:

```bash
# .env datoteka
JWT_SECRET=your-secret-key-change-in-production
JWT_EXPIRY_HOURS=24
MONGO_URI=mongodb://localhost:27017
MONGO_DB=music
```

## Sigurnosne Mere

1. **Token Expiration:** Tokeni ističu nakon konfigurisanog vremena
2. **HMAC Potpisivanje:** Koristi se HS256 algoritam sa tajnom lozinkom
3. **Role-Based Authorization:** Svaka zaštićena ruta zahteva odgovarajuće dozvole
4. **Token Validacija:** Svaki zahtev validira token pre nego što se obradi

## Error Kodovi

- `401 Unauthorized` - Nedostaje ili nevažeći token
- `403 Forbidden` - Token je valjan ali korisnik nema dozvolu
- `400 Bad Request` - Neispravan unos

## Testiranje sa cURL

```bash
# Registracija
curl -X POST http://localhost:8080/register \
  -H "Content-Type: application/json" \
  -d '{
    "username": "testuser",
    "firstName": "Test",
    "lastName": "User",
    "email": "test@example.com",
    "password": "TestPass123!",
    "confirmPassword": "TestPass123!"
  }'

# Potvrda registracije
curl -X POST http://localhost:8080/register/confirm \
  -H "Content-Type: application/json" \
  -d '{"token": "<verification_token>"}'

# Prijava korak 1
curl -X POST http://localhost:8080/login \
  -H "Content-Type: application/json" \
  -d '{"username": "testuser", "password": "TestPass123!"}'

# Prijava korak 2
curl -X POST http://localhost:8080/login/verify \
  -H "Content-Type: application/json" \
  -d '{"otp": "<otp_code>"}'

# Pristup zaštićenoj ruti
curl -H "Authorization: Bearer <jwt_token>" \
  http://localhost:8080/api/protected
```
